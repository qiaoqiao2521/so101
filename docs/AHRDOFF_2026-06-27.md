## 10. 下一步建议

### 方向 A: 先彻底绕开 Gazebo 物理

目标:
- 不再用 ros2_control
- 不再用 Gazebo joint physics
- 只做视觉复现

做法:
1. 在 Gazebo 里不 spawn 机械臂为 articulated URDF
2. 用 robot_state_publisher/RViz 或自定义 link pose publisher 算每个 link 的姿态
3. 在 Gazebo 中把每个 link 当独立 visual model 更新 pose

这条路可以保证"动作看起来复现", 不依赖物理控制。

### 方向 B: 继续修 Gazebo 物理

重点不是前端, 而是:

- 为什么 `GazeboSystem` 初始化后 joint actual position 是:
  - pi
  - 2.094
  - -1.5708
  - 1.5708
  - -3.107
  - 1.5708
- 为什么 actual velocity 是 `.nan`
- 为什么 `<gazebo reference="base_link"><kinematic>true</kinematic>` 只对 base_link 生效, 其他 link 仍可能被物理炸
- 是否 collision 简化体互相重叠, 启动瞬间把关节状态打爆
- 是否 inertia / joint axis / joint limits 和 GazeboSystem 不兼容

建议下一步先把 follower URDF 的 collision 全去掉或全部 `<collide_without_contact>false`/`self_collide false`, 再试 controller。

### 方向 C: 只用 RViz 完成闭环演示

当前最稳定路线:

```text
mint action_templates.json
  -> mint_joint_map.identity.yaml
  -> /joint_states
  -> robot_state_publisher
  -> RViz
```

这条路线已经能按帧播放, 不受 Gazebo 物理影响。
