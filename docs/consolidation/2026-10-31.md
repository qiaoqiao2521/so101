# SO101 四仓合并审查与迁移候选

日期：2026-10-31（北京时间）。这是源码审查与本地迁移候选；远程仓库、默认分支、部署和可见性均未修改，旧仓库未删除。

## 结论与目标

截图中的四个仓库最终保留 `qiaoqiao2521/so101` 一个开发仓库。保留现有 MuJoCo 仿真、轻量动作终端和真实验收资料；恢复值得复用的旧 Vue 前端与采集工具；资料站以 `apps/resources/` 合入，继续独立构建发布。

不把旧 Gazebo／Java MES／Electron 三套技术栈重新设成三个产品。也不把四库源码归并等同于当前车臂产品完全单仓：正在使用的网页与运行适配层仍在 FishBot 工作台分支。

## 关键发现：旧内容并未完整迁入

主仓 `workspaces/so101_ws/` 有 281 个零字节文件。前端 60 个文件中，40 个为空，涉及 4 个 API 模块、21 个 Vue 组件、6 个 composables、8 个业务函数文件和 1 个音频。现有 App、样式及测试仍引用这些文件。

旧 `so101_ws` 的 1,833 个 blob 中，501 个同路径同内容、81 个相同内容位于其他路径、153 个同路径内容不同、1,098 个未找到同路径或同内容。1,098 不能等同于 1,098 个有用功能：其中大量是生成记录与历史证据，但还包含独有源码。另有 134 个旧库非空而主库同路径为空的文件。前端是优先恢复的一部分，不代表已经救回全部历史。

额外分类的1,192个未完整迁入路径中，1,081项属于验收历史与录制资产，17项为配置模型，93项为源码及说明，1项为上游引用；没有将它们计作构建缓存。仅docs/generated就有1,034项、约42.3MB记录，另有约14.8MB的实际OBJ模型。删除旧库前应独立备份这些历史资产，不让日常源码维护承担所有产物。

## 更适合作为主界面的现有实现

主仓产品化计划已明确：当前网页／runtime 属于 FishBot 仓库的 `apps/fishbot-control-station/`，通过 SO101 根目录调用现有执行器，不在本次四个仓库内部。

核查时：
- 仓库为 `qiaoqiao2521/fishbot-ros2-slam-tools`。
- 5186 工作台在 `codex/workbench-code-rebuild-20261018` 分支，提交 `d7170c75c70a637baffb998a2edd7ddab02a5eb6`，不是默认 main。
- `workbench-preview.cjs` 提供工作台；`so101-runtime.cjs` 调用 `SO101_ROOT/experiments/colab-twin/station_executor.py`；`so101-live.cjs` 调用 `station_scene.py`。
- RobotStation／EpisodeReview 已有工位配置、运行状态、配方与回放相关实现，实际功能边界以源码和运行证据为准。

现代工作台还有一个真实产品缺口：现有EpisodeReview可查看已转换的MCAP与证据，但当前SO101任务产物默认注册报告和视频，未看到每次新任务自动生成并绑定独立MCAP的完整链路。历史回放入口不能代替“这一回合的3D回放”。任务落盘、原ID重查和取消继续均有源码，但本次没有做运行验证。

因此本次只把截图中的四库收成一个 SO101 仓库，记录对该工作台的外部依赖。未把 FishBot 第五个仓库纳入删除名单，也未迁它的工作分支或宣称其运行已复验。
