# SO101 可复用工位产品化

## Goal / User Intent

让用户在已有网页中移动工件、选择上料或卸料配方、运行并观察真实抓放；遇到可恢复偏差时能重新定位和尝试，再把工位接入 FishBot 连续配送。先增加可使用的能力，再优化节拍，不恢复同配方视觉 ACT 补训。

承接 [F2 工位与算法工厂](../factory-loading-20261021/task_plan.md)。保留已验收默认 `loaded_jaw_preload.py`、原裁判和失败记录。2026-10-24 本轮仅编写计划；下述新增能力均未实现。

## M1a — 先测工作区，再扩接口

1. 核对 base、shoulder_pan、pinch/tool、相机、目标坐标。用实际 FK 验证零位、安装偏移和工具轴；不能把世界 `atan2` 直接当关节指令。
2. 保留当前 IK 为对照。区分位置／竖直轴误差、wrist-roll 偏好和总残差要求；如改目标函数，单列适配候选和原几何误差，不靠放松安全阈值获得可达。
3. 在 ±10mm 区内外选中心、径向／切向边界及至少两个已有工位。先筛 FK/IK、关节余量、碰撞，再对筛选通过点做原整程物理。
4. 将径向角作为候选排序或姿态偏好。保留原 GraspGen-X 候选，按对象允许对称性产生新候选。姿态改变后重新评分／认证，不能继承原候选分数冒充新分数。
5. 核图像定位误差、遮挡／无目标拒绝和尺寸／朝向边界。当前俯视绿方块检测不能直接覆盖旋转零件、圆柱与新高度。
6. 只对有证据区域更新输入合同、`describe()` 和网页提示。边界外给具体原因；不直接删掉 ±10mm 校验。

**验收：** 发布米制、带 frame 的实测有效区域，逐点区分定位、IK、全路径、物理抓放。成功点须完成真实夹起、搬运、放稳、释放、脱离、回位；包含边界外、遮挡、姿态不支持负例。原中心和已有工位不退化。±150mm 只是探索范围，少量点或 IK 成功不能证明全扇区。

## M1b — 快慢交接不丢安全责任

沿 F2cf 实测叶段继续，先列回位认证、闭爪 244 扫掠、worker 准入、实测配置检查、GC／日志的线程及阶段。inclusive 时长不相加，不再盲扫数组参数。

- **慢环：** 复用 worker 准备定位／候选、IK、路径和认证。结果携带轨迹时间基、起始 achieved-q、场景／货物／夹爪上下文、有效包络和取消状态。worker 不写活动 `MjData`。
- **快环：** 原物理 owner 插值、推进、读实际关节／接触并执行原守卫。旧轨迹失效执行原安全行为，不因新规划未就绪而盲开。
- **交接：** 保留 achieved-q 桥接、首指令认证、释放物检查。认证迁出前须证明覆盖实际跟踪包络、全 244 点和上下文变化；证明不足则保留原检查，不能跳过后报提速。
- **调度：** 记录计划释放、实际开始／结束、等待和源时间。将非必要文件 I/O 移出控制线程；预热在激活前且单列启动成本，不能删首拍后改称完整通过。

**双层验收：** servo-only 单列；原完整周期继续包含感知、调度、守卫、worker 交接及闭爪／释放／回位切换。每轮给样本数、P50/P95/P99/max、>20ms 和截止期违约数。3–5ms 是目标；P99<20ms 不等于零慢拍。仅冻结完整回合全部受测拍 ≤20ms、无截止期违约且原物理通过，才记“该面板完整 50Hz 通过”，不称通用硬实时保证。

## M2 — 六技能复用原执行器

先给原阶段加可观察、可取消适配，旧八步及 `pick → transfer → place` 保持可复跑。只允许满足前后置条件的组合，首版不开放任意脚本。

| 技能 | 前置条件 | 成功后置条件 |
| --- | --- | --- |
| Locate | 当前相机／frame 有效、目标可见 | 有时效和质量的估计；遮挡／未知拒绝。 |
| Approach | 候选完成 IK／碰撞及现场准入 | 实际到达预抓取包络。 |
| Grasp | 下降／闭爪扫掠已认证 | 原双指接触、真实抬升／持物成立。 |
| Carry | 持物、运输路径有效 | 到达放置包络，原持物／碰撞守卫持续成立。 |
| Place | 支撑和释放路径有效 | 原静稳、开爪、自由物体、释放审计通过。 |
| Retreat | 已释放，实测物体／环境可避让 | 释放物避碰、脱离、回位完整通过。 |

复用成熟行为树实现，优先核现有 ROS/Nav2 所用 BehaviorTree.CPP 的版本、许可和适配边界。先验 `RUNNING` 非阻塞、halt、原 task ID 与 worker 清理；不为 Python 控制器强制整体迁 C++，不自造树引擎。

**恢复顺序：** 抓空／失物 → 中止原运动并确认停止 → 核物体支撑、可见性与可认证撤退路线 → 重新 Locate／Approach／Grasp。不能无条件上抬；滑落物、盘壁或车体可能位于撤退路线上。不可见、掉出台面、未知路线、无进展或取消时安全停止。验收前固定重试策略与总截止期，重试不重置计时。

先核原 monitor 是否首失败即终止。原 attempt 失败不得删除；若旧裁判不能表达恢复，独立 recovery profile 按各 attempt 的原物理结果汇总，不修改旧 verdict 或回填旧单次成功。任务恢复、首次成功、安全停止、取消分列。

## M3 — 冻结验收，不边考边调

- 开发集用于修复。冻结前声明点位、目标 yaw、扰动时机／幅值、接触与观测模式、种子、重试和原物理条件。旧 ACT 扰动分布不能无说明套给新控制器。
- 最小可判定集先淘汰明显失败，开发通过后运行 20 正常＋20 全新扰动。失败、未注入、缺证回合全部保留；未注入不算抗扰动成功。
- 沿用此前目标：正常 20/20、扰动 ≥17/20，安全停机和障碍接触为 0。宣传 40/40 需另达更高目标；有效安全停止仍计任务失败。
- 同时报告规划、任务仿真、进程 wall/CPU、完整周期、抓放／掉物／重抓、释放、脱离、回位、取消。节点返回和录像不能替代物理结果。
- 冻结失败保留本轮；改动后另立版本和独立留出集，不调阈值或只补失败项拼成绩。

## M5 — 自动寻优作为后续产品能力

沿用 CLI、候选目录、原评测与报告，提供“选目标 → 最小筛选 → 原物理对照 → 可撤销采用”；不新建平台。

- 固定模型、初态、进程首次 requested/effective seed、OMPL 创建／调用顺序，保留实际路径。路径相同时分析运行开销；路径变化另报长度、节拍和规划成本。seed 不保证 wall 相同。
- 局部至少三对、输出等价才进入原物理；先主工位 B→C，再另一已有工位 C→B。收益小于噪声时针对性重复；不一致不晋级，不跨 VM／负载累加秒数。
- 区分实现优化与工艺设计：候选顺序／安全净空仅在已有允许域内试验；托盘平移、底座高度、外廓改变是新布局，独立 scene/profile 重验。托盘倾角、新物体暂不进首版。
- 原超时、碰撞余量、采样分辨率、评分和力矩限值不作为优化参数。loaded_jaw_preload 仅在原允许域内讨论，不以放松饱和获得收益。
- 同时优化成功、安全、节拍与恢复成本。20+20 用于冻结晋级，不给每个变体都跑；网页展示实测收益、负例、适用范围。无可靠收益不换默认。
